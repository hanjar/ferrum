# Compare/Sync: scan cepat (FER-472)

Mengukur fase scan `compare_dirs` (rekursif, tanpa mode konten) sebelum dan sesudah tingkat A (`FindFirstFileExW` +
`FindExInfoBasic` + `LARGE_FETCH`, plus look-ahead paralel). Desain: `docs/compare-sync.md` bagian FER-472.

## Cara menjalankan

```powershell
cd src-tauri
$env:CARGO_BUILD_JOBS=4
cargo build --release --example bench_compare_scan
# dataset uji: 2 x 100.000 file (right: 1% beda ukuran, 1% beda mtime, sedikit satu-sisi)
.\target\release\examples\bench_compare_scan.exe gen C:\dev\ferrum-bench 100000
.\target\release\examples\bench_compare_scan.exe run C:\dev\ferrum-bench\left C:\dev\ferrum-bench\right 3
# separuh tingkat B yang berjalan di memori (tanpa admin)
.\target\release\examples\bench_compare_scan.exe mft-synth 1000000
```

"Sebelum" = binary yang sama dibangun dari `main` @ `ac0bedd` (walker lama: `read_dir` + `symlink_metadata` per file,
berurutan). "Sesudah" = branch ini. Harness hanya memakai API publik yang tidak berubah, jadi kedua binary
menjalankan kode scan masing-masing dengan input yang sama.

## Hasil (host owner, Windows 11, NTFS lokal SSD, cache metadata hangat, PC dipakai bersamaan oleh sesi lain)

Dataset uji 2 x 100.000 file (102.022 entri, 2.002 berbeda, 0 error; identik sebelum dan sesudah):

| Walker                     | Run 1..3               | Median |
| -------------------------- | ---------------------- | ------ |
| Sebelum (`read_dir`+lstat) | 4,06 s, 4,14 s, 4,64 s | ~4,1 s |
| Sebelum, putaran 2         | 4,16 s, 6,13 s, 5,93 s | ~5,9 s |
| **Sesudah (tingkat A)**    | 89 ms, 80 ms, 83 ms    | ~83 ms |
| Sesudah, putaran 2         | 77 ms, 76 ms, 74 ms    | ~76 ms |

Sekitar **50x** pada cache hangat. Angka ini sengaja dibaca hati-hati: kedua sisi 100k file ada di cache metadata,
sehingga listing nyaris gratis, sedangkan jalan lama membayar satu `CreateFile` per file.

Pohon nyata `C:\Users\you\Drive` dibandingkan dengan dirinya sendiri (608.775 entri per sisi, 0 selisih, 0 error;
sama sebelum dan sesudah). Cloud sync client dan antivirus ikut aktif, jadi angka berfluktuasi:

| Walker                  | Run                          |
| ----------------------- | ---------------------------- |
| Sebelum                 | 84,5 s, 53,4 s               |
| **Sesudah (tingkat A)** | 13,1 s, 5,1 s, 6,3 s, 13,5 s |

Sekitar **4x pada angka terburuk dan 10x pada angka terbaik** (53 s / 5,1 s) untuk 740k-class tree.

## Tingkat B (MFT, UAC)

Diuji lewat unit/paritas, tidak diukur end-to-end (butuh UAC, langkah manual di `docs/compare-sync.md` / laporan task).
Yang bisa diukur tanpa admin adalah separuh di memori: `MftSource::build` + listing semua folder untuk volume sintetis
1.000.000 file / 20.000 folder: **67 ms build + 48 ms listing**. Biaya tetap tingkat B adalah baca MFT SELURUH volume
oleh helper (FER-460: ±9 s untuk `C:\` dengan 4,9 juta record, ditambah UAC dan transfer pipe), berapa pun kecilnya
subtree sync. Jadi untuk subtree di volume besar yang sudah cache hangat, tingkat A (±5 s untuk 600k entri) bisa setara
atau lebih cepat dari B. B terutama menang pada cache dingin, disk lambat, dan volume kecil.
