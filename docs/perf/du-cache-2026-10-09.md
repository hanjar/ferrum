# Disk usage: cache scan di disk untuk root di luar indeks (FER-464)

Ukuran file cache dan waktu muat untuk root besar. Desain dan keamanan: `docs/disk-usage-contract.md` §8.

## Cara menjalankan

Tidak ada drive non-NTFS besar di mesin pengukur, jadi pohon sintetis dengan proporsi drive sistem (4 level, ±7 file per
folder, nama campuran) dibangun di memori, disimpan, lalu dimuat kembali ke snapshot:

```powershell
cd src-tauri
$env:CARGO_BUILD_JOBS=2
cargo test --release --test disk_usage_cache_bench -- --ignored --nocapture
```

`FERRUM_BENCH_FILES` dan `FERRUM_BENCH_DIRS_L4` mengecilkan pohon untuk percobaan cepat.

## Hasil

Diukur 2026-10-09, branch `feature/fer-464-du-cache`, build release, SSD lokal, saat PC juga menjalankan build lain.

| Ukuran pohon (sintetis)                                      | File cache              | Simpan (save) | Muat (load) |
| ------------------------------------------------------------ | ----------------------- | ------------- | ----------- |
| 3.234.289 file, 490.105 folder (setara `C:\` ±3,3 juta file) | 50.671.945 B (48,3 MiB) | 4,8 detik     | 1,7 detik   |

- "Muat" = baca file, dekompresi, validasi CRC, dan bangun peta node + daftar file (snapshot siap di-query). Bandingkan
  dengan scan biasa `C:\` ±63 detik dan scan MFT ±11 detik (FER-460).
- "Simpan" berjalan di worker scan SETELAH event `done`, jadi UI tidak menunggu. Termasuk kompresi deflate level 3,
  `sync_all`, dan rename atomik.
- Rata-rata 15 byte per file. Nama file di benchmark acak (hex), jadi nyata kemungkinan lebih kecil karena nama asli
  lebih berulang. Angka ini batas atas yang konservatif; ukuran nyata di drive pengguna belum diukur.
- Batas total 512 MiB untuk 8 root; satu root sebesar `C:\` memakai kira-kira 10 persennya.
- Memori saat muat sama dengan hasil scan biasa (snapshot yang sama di RAM, tunduk pada `MAX_STORED_ENTRIES`).
