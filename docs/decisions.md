# Keputusan proyek — Ferrum file manager

Dokumen ini adalah catatan keputusan (decision log) proyek. Setiap task baru wajib membaca
dokumen ini dan menambah entri bila ada keputusan baru. Format: tanggal, keputusan, alasan.

## Konteks

Brief awal 27 September 2026: file manager desktop dual-pane, Rust untuk I/O filesystem,
Svelte untuk UI, IPC eksplisit bertipe.

## Desain awal

Prototipe awal memuat seluruh layout: titlebar 40px, sidebar 208px (Places/Tree), dual pane (grid 2
kolom, gap 1px), tab strip 36px, toolbar 36px (back/forward/up, breadcrumb, filter, view
switcher details/list/grid), header kolom 26px, row 26px (`--row:26px`), status bar 28px
per pane, keybar bawah 30px, plus modal: command palette, dialog copy, panel antrean,
preview, settings, context menu.

Fitur **di luar MVP**: AI assistant, compare folders, preview
panel, search in-pane. Semua itu tidak dikerjakan pada task 01–15; UI shell boleh menampilkan tombolnya sebagai non-aktif
atau tidak menampilkannya sama sekali sampai task-nya ada.

## F2-01 — Backend arsip (2026-09-28)

**Keputusan:** pilih `zip` 4.6.1 (fitur `deflate`, `aes-crypto`; default nonaktif) untuk ZIP dan `sevenz-rust2` 0.20.2 (`compress`, `aes256`; default nonaktif) untuk 7z. Pertahankan `unrar` 0.5.8 sebagai kandidat pembaca RAR **bersyarat**, tidak ada pembuat RAR. Spike standalone Windows berhasil membuat, mendaftar, membaca lewat stream, dan menguji fixture ZIP/7z legal, termasuk AES dan kasus korup; RAR hanya berhasil di-link, belum lulus fixture konten. Kontrak aplikasi/UI belum berubah. Detail kemampuan, pengukuran, fixture, sumber lisensi, dan batas ada di `archive-support.md`.

**Alasan:** kedua backend Rust memenuhi roundtrip host tanpa executable eksternal; 7z alias `.7zip` harus lolos deteksi signature. UnRAR menyertakan C++ vendored dengan lisensi berbeda dari wrapper dan pembatasan algoritma RAR; sebelum rilis harus dipastikan notice dan build lintas OS serta fixture RAR legal. Windows memerlukan `Advapi32` selain link bawaan `unrar_sys`; contoh spike menautkannya eksplisit. Alternatif `libarchive`/sidecar tidak diuji sehingga bukan keputusan dukungan. Jangan nyalakan ekstraksi ke direktori pengguna sebelum pipeline keamanan F2-03 selesai; `../outside.txt` diterima sebagai nama entry oleh kedua pembaca.

## F2-02 — Lokasi virtual arsip (2026-09-28)

**Keputusan:** gunakan `Location` discriminated disk/archive dengan identitas `(archivePath, memberPath)`; member slash-relatif dan bukan path OS. Parent root kembali ke direktori disk pembungkus, nested archive ditunda, selection memakai identitas member, sort/filter metadata tanpa membaca payload. Token monoton untuk listing per tab menolak respons lama sebelum parsing; lokasi tab/history kelak menyimpan union ini. `ArchiveProvider` menetapkan list/read bounded/extract/create/test dan error/progress/conflict, namun backend/handler Tauri/pane masih belum terpasang. `archive-support.md` mencatat batas F2-02 dan gate; kontrak tidak dianggap fitur arsip aktif. **Alasan:** file ownership board melarang mengubah `lib.rs`, `ipc.rs`, pane UI di lane ini; menambahkan command tanpa engine akan menjadi no-op menyesatkan. Integrator wajib menghubungkan backend nyata dan mendefinisikan payload IPC sebelum F2-02 dinyatakan selesai.

## Asumsi

- Pengguna punya hak menulis ke direktori yang dibuka; aplikasi tidak membatasi akses ke
  lokasi arbitrer (file manager sejati), validasi path hanya untuk bentuk path yang sah
  (bukan path kosong/invalid), bukan sandbox.
- Bahasa UI: Inggris (sesuai prototipe). Bahasa dokumentasi proyek: campuran
  Indonesia/Inggris mengikuti brief awal.

## D50 — Interface font scale bernama S/M/L/XL (2026-09-30, Appearance/FER-370)

**Keputusan:** Interface font size diganti dari angka fix 12/13/14 px menjadi empat level bernama Small/Medium/Large/Extra Large — offset global `--uiStep` (−1/0/+2/+4 px) yang dijumlahkan ke basis px tiap aturan teks di seluruh app (menu, sidebar, list, dialog; preview dokumen dikecualikan). Baris list terkopling: `rowPx = max(density, ceil((13+step)×1.85))`. Prefs: `uiFontLevel: s|m|l|xl`, migrasi `uiFontSize` angka 12/13/14 → s/m/l.

**Alasan:** set absolut menghancurkan hierarki antar bagian (basis tiap bagian berbeda) dan 13→14 px tidak terlihat; level bernama + offset relatif menjaga proporsi, memberi lompatan yang terasa (L +15%, XL +31%) untuk aksesibilitas, dan membuat konversi permukaan baru mekanis. Deviasi dari mockup v3 (dropdown "13 px") disetujui pengguna langsung 2026-09-30.

## D51 — Kebijakan akhir baris dan format (2026-10-07, FER-443)

**Keputusan:** Repo memakai LF di index dan di working copy (`.gitattributes`: `* text=auto eol=lf`). Prettier tetap `endOfLine: lf` (default); `contract-fixtures/` tidak diformat. Commit reformat mekanis `37ced6d` ada di `.git-blame-ignore-revs` (aktifkan dengan `git config blame.ignoreRevsFile .git-blame-ignore-revs`).

**Alasan:** `core.autocrlf=true` di Windows membuat working copy CRLF sehingga `prettier --check` menolak ratusan file yang indeksnya sudah LF. `eol=lf` menimpa `autocrlf`, jadi checkout baru tidak drift lagi.

**Prosedur untuk branch lama yang dibuat sebelum `37ced6d` (konflik format saat merge main):**

1. `git merge main`. Konflik yang hanya soal format: ambil sisi branch dengan `git checkout --ours <file>` (kamu sedang di branch-mu), atau sisi main dengan `git checkout --theirs <file>` bila branch tidak mengubah file itu secara logika. Konflik logika diselesaikan manual.
2. `npx prettier --write .`
3. `git add --renormalize .` (menyamakan akhir baris dengan `.gitattributes`).
4. Jalankan `npm run format:check`, lalu commit merge. Jangan campurkan perubahan logika ke commit reformat.
