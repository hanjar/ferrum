# Ferrum 0.2.1 — known issues

Platform: Windows 10/11 x64. Base `main` @ `da980a0`. Pre-release, unsigned installer.
Severity: **High** = data loss or crash with normal use; **Medium** = a wrong claim, a safety gap with a workaround, or a missing guarantee; **Low** = cosmetic, docs, or an edge case.
No High issue is known. Items keep their 0.2.0 IDs. Previous list: [`../v0.2.0/KNOWN-ISSUES.md`](../v0.2.0/KNOWN-ISSUES.md).

## B. Archives

| ID    | Sev | Issue                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Workaround / note                                                 |

The UI shows the reason and the backend refuses it.                                                                                                                                                                                                                                                                           | Unpack with Alt+F9, then checksum or compare the file.            |
| KI-09 | Low | RAR creation needs your own WinRAR 7.00 or newer (`Rar.exe`). Ferrum does not ship it and cannot create the old RAR4 format. Without a validated `Rar.exe`, RAR is not offered in the Pack dialog.                                                                                                                                                                                                                                                             | Pack to ZIP or 7z.                                                |
| KI-10 | Low | RAR tests build their fixtures with the tester's own `Rar.exe` and skip when it is missing, so CI does not exercise them. | KI-11 | Low | 7z limits: compare and member reads are refused when a solid block or codec dictionary needs more than 256 MiB ("solid block/codec memory too large"). Reading one member of a big solid block still decodes the members before it, within a 256 MiB / 5 s budget. Quick View and compare decode on one thread.                                                                                                                                                | Prefer non-solid 7z or ZIP for large sets, or unpack with Alt+F9. |
| KI-12 | Low | Cancelling Quick View of a RAR member only stops at member boundaries; a single UnRAR `skip()`/`read()` cannot be interrupted.                                                                                                                                                                                                                                                                                                                                 | Bounded by the size and time budget.                              |
| KI-13 | Low | Deferred review items, all safe failures: a very repetitive ZIP member of 64 KiB or more with ratio above 200x is refused for preview; a real disk folder named like `x.zip` is treated as an archive by Quick View; one invalid sibling name or one encrypted RAR member makes the whole RAR listing fail; ZIP member names with backslashes are not found; `archive_read` of a 7z with a wrong password reports a corrupt archive instead of a bad password. | Unpack the archive instead.                                       |
| KI-14 | Low | Extraction publishes into a destination root that is opened without following links and identity-checked (#19), but links in the **ancestors** of the root path are still resolved by the operating system.                                                                                                                                                                                                                                                    | Extract into a directory only you can write.                      |
| KI-15 | Low | Not reproduced in this release (carried over): navigating up out of an archive with the `..` row was once reported to show an error toast.                                                                                                                                                                                                                                                                                                                     | Use Backspace or the breadcrumb.                                  |
| KI-27 | Low | Behaviour change: file operations that change anything on an administrative share (`\\server\C$`, `ADMIN$`, drives mapped to them) or on a UNC path that points to this computer are refused (browse and read still work). Ferrum's own config, data and Activity folders cannot be a target of file operations.                                                                                                                                               | Use Explorer for such targets, or a normal share.                 |
| KI-28 | Low | `Rar.exe` must sit in a folder that other accounts cannot write to (for example `C:\Program Files\WinRAR`), and not on a network drive; otherwise Ferrum refuses it. Selection files are saved only as `.json` or `.ferrum-selection`.                                                                                                                                                                                                                         | Install WinRAR in Program Files.                                  |
| KI-29 | Low | Some defense-in-depth hardening against a compromised UI is still open. Known gaps: a share that maps onto a protected Ferrum folder through this PC's LAN IP address or a hosts-file alias is not recognised (FileId comparison costs several SMB round trips per operation); non-surrogate reparse points (for example OneDrive placeholders) above `Rar.exe` are not refused. None of it affects normal use.                                                | None needed.                                                      |
| KI-30 | Low | Files whose name is a Windows device name (for example `nul` or `con.txt`, typically created by WSL or scripts): copy and move now keep their content (#29), but such an entry cannot be sent to the Recycle Bin (Ferrum refuses with a message), and a reserved-name child inside a plainly spelled folder fails on its own item instead of being copied.                                                                                                     | Delete such an entry permanently, or rename it first.             |
| KI-16 | Low | Moving a file loses its comment: comments live in a per-folder sidecar (`.ferrum\comments.json`). Rename migrates the comment, move does not.                                                                                                                                                                                                                                                                                                                  | Documented limitation.                                            |
