# Audit engine sync dua arah (FER-211 / AI-10.1)

Base: `feature/ai-assistant` @ `64fc71ead75ec7b5c4accacba8b683a16fafebe4`. Audit read-only terhadap engine F2-18 (compare) dan F2-19 (synchronize). Acuan: `coordination/plans/phase-3-ai-assistant-glm.md` bagian 6, 8, 12. Bukti dirujuk `file:baris` pada base tersebut. Status "teruji" berarti ada tes yang benar-benar menjalankan perilakunya, bukan sekadar kode ada.

## 1. Apa yang sebenarnya ada

Tidak ada "service sync" di Rust. Engine sync = tiga potong terpisah:

1. **Compare satu level** `src-tauri/src/compare.rs:249` `compare_dirs` (read-only, lstat, toleransi mtime 2 s `:20`, mode isi opsional `:289`). Kunci nama dibandingkan persis-huruf (`:241`, `:276`).
2. **Perencana murni di frontend** `src/lib/syncPlan.ts`: `classifyEntry` (`:38`) memetakan state compare ke aksi; `isPlanStale` (`:124`) membandingkan ukuran/mtime snapshot.
3. **Eksekusi di store** `src/lib/stores/compareStore.svelte.ts:206` `executeSync`: re-compare, cek stale, lalu `enqueueCopy(..., 'overwrite')` ke queue/copy engine existing (`src-tauri/src/copy_engine.rs:183` `run_copy`). Delete diarahkan ke dialog konfirmasi (`:253`).

Yang TIDAK ada sama sekali (grep `baseline` di `src`/`src-tauri/src` hanya menemukan `disk_usage`, tidak terkait): baseline/riwayat sync per pasangan root, identitas root, penyimpanan lokal berversi, fingerprint isi untuk keputusan sync, keputusan konflik per item, hasil sync per item.

### Handoff (bukan milik lane ini)

- **H1 (Lane C `compareStore.svelte.ts` / `syncService.ts`):** panggil `validate_sync_roots` (butuh command IPC baru: `ipc.rs`/`lib.rs`) sebelum `openSync` dan `executeSync`; jalankan `compareDirs(..., byContent=true)` untuk sync; berikan `baseline` ke `buildSyncPlan`; tolak eksekusi bila `syncPlanBlockers(report)` tidak kosong; jangan menjalankan item `conflict`. Revalidasi lagi tepat sebelum enqueue.
- **H2 (pemilik IPC/store):** persistensi baseline lokal berversi per pasangan root (ambil/simpan `SyncBaseline`); baseline rusak/tak dikenal dikembalikan sebagai `null` (first-run).
- **H3 (Lane C/AI-06):** simpan operation ID per aksi dan petakan hasil job ke `ItemOutcome`; setelah job terminal, jalankan compare segar dan panggil `reconcileBaseline`, lalu simpan baseline (hanya hasil terverifikasi).
- **H4 (UI):** `SyncPanel.svelte` perlu menampilkan alasan conflict dan pilihan kiri/kanan/keep both/skip per item (belum ada).
- **Perilaku yang berubah:** `both` tanpa baseline tidak lagi meng-update otomatis ke sisi "lebih baru"; hasilnya conflict. `syncFlow.test.ts` disesuaikan (dua tes).

### Batasan yang tetap berlaku

- Sync masih satu level (isi subfolder yang ada di kedua sisi tidak disinkronkan).
- Belum ada fixture E2E dua tree yang disinkronkan oleh alur UI/executor; klaim "dua arah lengkap" TIDAK dibuat. Yang terbukti: perencana (unit), primitif Rust (fs temporary), dan union converge pada primitif.
- Mtime tidak dipertahankan pada copy di base ini (FER-393); baseline mencatat fakta dari compare segar pascarun, bukan asumsi.
- Cancel/permission/full-disk di tengah overwrite: belum dijamin sampai FER-393 ter-merge.
- Restart/`unknownOutcome` dan idempotency key: di luar engine sync (AI-06).
