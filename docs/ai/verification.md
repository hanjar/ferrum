## 6. Known limitations (release boundaries)

- **Windows only.** This release covers Windows 11 x64; no other OS is claimed.
- Only the provider/model configured for the smokes was exercised live, one run per scenario. A live model is non-deterministic, so a
  passing run is evidence, not a guarantee. Endpoint and model are user configuration.
- ZIP: Pack runs in-process without job id, progress or cancel (LIMIT-6). A 100,000-file folder took 16.5 minutes with no progress in
  the card; a cancel during Pack is refused honestly and the real result follows.
- ZIP failures mid job (row 19): an unreadable input is proven on the desktop (`Failed` + cause). A **full disk** and an **ACL
  permission denial** are proven only by engine/executor tests, not on a real drive or ACL — release limitation.
- `unknownOutcome` "Check result" (LIMIT-4) is tested automatically; no desktop run produced a real `unknownOutcome`.

### Design decisions (not defects)

- **`ConflictPort` waived (FER-162, option B, decided 2026-10-05).** The executor and `approval.ts` keep the `ConflictPort`
  interface, but no port is wired in the app. Chat never asks the user to resolve a conflict and never picks a winner: ZIP
  output collisions use the engine's `skip`/unique-name policy, and chat sync lists conflicts and skips them. The user resolves sync
  conflicts in the manual Sync panel through "Resolve in Sync panel" (`6cc8c71`). WP1 (FER-163, `529b3e6`) records the same
  waiver. Wiring a chat conflict dialog would be a new feature, not a fix for this release.
